# 首轮结论与下一阶段决策

最终采用 `results/smoke-02/`。这是 OPT-125M 单机机制验证，未下载更大模型、未实现两机系统、未验证真实 chunked prefill 或在线 SLO。原版 `flexllmgen/` 与 benchmark 未修改。

## 实测 E0：原版 overlap 的收益有限，存在负结果

代表配置：padding 后长度 128、microbatch=1、microbatch 数量=1、固定生成 16 tokens；预热 2 次，正式采样 7 次。

|策略|端到端 P50 ms|P95 ms|
|---|---:|---:|
|全 GPU|43.15|43.36|
|CPU 权重，串行|433.35|433.50|
|CPU 权重，原版 overlap|418.53|419.33|

12 组 CPU 策略对照的 serial/overlap 耗时比为 0.973–1.051。microbatch 数量为 1 时约改善 3–5%；为 2 时多数配置持平或略差。36 个配置的生成 token IDs 均与对应全 GPU 基线完全一致。

**支持什么：** 在本机的小模型强制 offload 条件下，本地 overlap 并未隐藏绝大多数搬运成本，有继续测量必要条件的价值。
**限制什么：** 125M 本来能全部驻留 GPU；人为 offload 比全 GPU 慢很多，不能作为实际部署建议。原版输入只有 7 个非 padding token，物理长度扫描不是在线长短请求测试。
**下一步：** 值得继续组件验证；扩大模型前需下载确认，真实服务实验前需更换为不同有效长度 prompt。

逐层 trace 对全 GPU 的扰动约 24%，对 CPU offload 路径约 1% 或更少；精确值见 trace summary。trace 单独运行，未混入正式吞吐。暴露权重等待只提供 CUDA 时间线 gap proxy；没有声称完成 CUPTI 级纯 H2D 因果归因。

## 实测 E1：小 batch 下搬运远长于计算

|完整 block 数|真实张量 pinned H2D P50 ms|有效 GB/s|
|---|---:|---:|
|1|1.119|12.67|
|2|2.237|12.68|
|4|4.470|12.69|
|8|8.915|12.72|

56 种计算形状中，H2D/compute 为 1.85–10.39。小 batch decode 通常接近 10 倍；batch=4、q=256 的普通 prefill 接近 1.9 倍。增加层组大小大致同时放大搬运与计算，未自动解决时间匹配。负载下 PCIe 为 32 GT/s（Gen5）、x4；空闲降速不能代替带宽测量。

**支持什么：** pinned 稳定态传输及真实层组计算可以稳定测量；更大 token 工作量更接近可利用的预取窗口。
**限制什么：** 本次没有找到 compute ≥ H2D 的形状，不能假设对端只执行一个同规模层组就足以完全隐藏下一组传输。q>1 全部是 past=0 的短 prompt 近似；decode 的历史 KV 来自真实 block prefill，但隐藏输入是合成张量。
**下一步：** 保留小 decode 与较大 prefill 两端配置，进入实际重叠和网络成本校准。

## 实测 E2：确实可重叠，但不等于系统收益

56 种独立 H2D+计算形状中，并发相对串行的 P50 makespan 加速为 1.061–1.526。结果包含 copy/compute 各自 slowdown，重叠效率没有截断到 [0,1]。8 条代表性双缓冲时间线通过数据就绪、旧读者完成后复用以及输出数值一致性检查。

**支持什么：** 本机独立 copy/compute 存在可用并发；事件管理的最小缓冲生命周期工作正常。
**限制什么：** 小 decode 能隐藏的只是较短的计算；E0 原版整模型收益仍小。微基准使用独立 buffer，尚未处理多请求权重复用，不能直接转化为 InferRelay 加速比。
**下一步：** E3 同时使用 isolated 与持续争用倍率；真正两机时重新测量并发 slowdown，不沿用本机比例作为定律。

## 预测 E3：有盈亏分界，必须实测校准

共 26880 个参数情景：15830 个预测改善超过 1%，3850 个预测退化超过 1%，其余为近似持平。计数取决于扫描网格，不是成功概率。以下只展示明确假设下的例子，完整正负结果均在 CSV 中。

固定假设：网络 2.5Gbps、单向时延 100µs、端点 staging 8GB/s + 每端 10µs、相同计算能力、双缓冲、单请求、isolated 争用情景。所有时间只覆盖 Transformer block stack；decode 用两个固定历史长度周期，prefill 用一个周期。

|层组|q / past / batch|连续切层预测 ms|接力预测 ms|预测速度比|
|---|---|---:|---:|---:|
|2|1 / 256 / 1|17.55|14.89|1.179|
|2|128 / 0 / 1|10.79|8.31|1.298|
|1|256 / 0 / 4|18.67|69.50|0.269|
|4|256 / 0 / 4|17.31|22.74|0.761|
|8|128 / 0 / 1|11.60|11.60|1.000|

**支持什么：** 事件模型可筛选值得做两机实验的配置；层组过细且 activation 较大时，额外通信足以抵消减少的等待。
**限制什么：** 模型没有 embedding/LM-head、真实异构 H2D、实测 NIC/DRAM 争用、GPU 权重驻留优化或多请求权重复用。模型使用可回填资源空隙的 FCFS 计算顺序，不是最优在线调度器。连续基线可选择所有层组边界切分；仍需真实实现验证公平性。
**下一步：** 值得在获得第二台机器后验证一组预测有利和一组不利配置；在此之前不能声称两机加速、SLO 改善或成本更低。E4/E5 验收方案见 NEXT_STAGES.md。

## 资源、验证与可复现性

- 全轮耗时约 163 秒；GPU allocated 峰值 565.19 MiB，进程 RSS 采样峰值 2.22 GiB，低于 4GiB/6GiB 预算，无 OOM。
- pinned live tensor 字节与 allocator 原始信息分别记录。观察到 host allocator 负计数时不采用 allocated peak；reserved peak 是进程累计口径。
- 5 项依赖/资源调度测试通过；最终原始数据、分位数顺序、buffer 时间顺序、36 配置输出一致性及源码 SHA256 均已复核。
- 每项预热至少 2 次、至少 7 个样本且至少采样 0.15 秒。P95/P99 是短实验的样本分位数，不能推断可靠的在线尾延迟；固定执行顺序还可能受 DVFS/温度漂移影响。
- `smoke-01` 是前一轮有效测量，但缺少 E1 每形状内存统计；`pilot-01` 是开发试跑，带有独立 VALIDATION_NOTES，不能用于正式 E3 结论。
- `results/smoke-02/source/` 用于核对或恢复到实验代码目录；运行入口仍是仓库根目录下的模块，不直接从 source 副本执行。
